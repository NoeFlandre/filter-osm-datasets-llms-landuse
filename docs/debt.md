# Known weaknesses

| Weakness | Reason | Cleanup path |
|---|---|---|
| The canonical generation for each text (dedup) ignores small GPU-numerics differences between duplicates. | Greedy decoding is deterministic only for one batch composition and one GPU. | This is acceptable by design (ADR-0005). The gate for each GPU limits the effect. |
| The project does not use day-time job extensions (`oarwalltime`, quota exempt). | The project sizes the work of each job to its walltime (plus 20 % overflow). An extended job has no work left. | This is useful only if the nodes can get more chunks during a job. Then extend the job in its last 10 minutes while the GPUs are free. |
| Local development on an external drive is slow. | Hardware. | Keep the venv and the work tree on the internal disk (`UV_PROJECT_ENVIRONMENT`, `LUF_WORK`). |
| Mutation testing and CRAP cover only the paths in `[tool.mutmut] source_paths` (`domain/` and some `application/` modules). | The other `application/` modules do I/O (controller, node, publish, sync, staging, site_cache, node_main, remote_publish, inventory, bench, calibrate, and `remote_plan`). The `run_plan` and `run_replan` loops of `remote_plan` depend on wall-clock checkpoints and bucket round trips. Its 55 unkilled mutants need a fake clock first. Other modules wait for their own tests (`locators`, `datasets`, `geo`, `locate`, `assemble`, `published_stats`). | Move decisions into pure functions (as `slot_for`). Then add each pure module to `[tool.mutmut] source_paths` (the Makefile's CRAP limits derive from it; issue #117). The SQL-case mutants of `plan.py` are on the allowlist as equivalent. |
| Coverage omits `cli/*`, `node_main.py`, `adapters/engine.py`, the tokenizer and `adapters/frontend/`. | They need a GPU, the real tokenizer, a node or Grid'5000. | Write Typer `CliRunner` tests with stubbed use cases for `cli/*` (issue #116). |
