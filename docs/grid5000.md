# Running on Grid'5000

The controller runs on your laptop; frontends only receive light commands
(`oarstat`, `oarsub`, `usagepolicycheck -t`, one status API call, rsync).

```bash
export LUF_WORK=~/luf-work
luf g5k inventory                      # GPU clusters of every site
luf bench plan                         # benchmark as work (parity first)
luf g5k run --datasets benchmark --gpu-models l40s --max-jobs 1 --once
luf status
luf g5k pause [--cancel]  /  luf g5k resume
```

* Jobs request one GPU for one hour (`--checkpoint 300`), only where GPUs are free
  now. Abaca (production) clusters get `-q abaca`; default-queue clusters follow
  the day/night rules (daytime: ≤ 1 h, immediate start, quota-exempt; night: `-t
  night`, ending before the next working-day 09:00).
* `usagepolicycheck -t` runs before and after every submission.
* Clusters that only admit the account in besteffort are remembered and skipped.
* Nodes write content-addressed parts to `~/luf/work`; the controller pulls them.
  No credential ever reaches Grid'5000.

## Keeping local disks empty (bucket mode)

With `--bucket NoeFlandre/landuse-filter-work`, chunk inputs and result parts live in
a private Hugging Face Bucket. Nodes download their inputs to node-local `/tmp` and
upload each part plus a tiny hash manifest as they flush; the controller only pulls
manifests and job summaries. Planning and publishing run as CPU jobs on node scratch:

```bash
luf g5k cpu-job plan    --site grenoble --dataset osm-polygon-website-tag --revision <sha>
luf g5k cpu-job publish --site grenoble --dataset osm-polygon-description-tag --revision <sha>
```

Nodes read a fine-grained HF token from `~/luf/hf_token` (mode 600), placed by the
owner; it is exported to the job environment only.

## GPU admission

Each GPU type is admitted once by running the full benchmark in its own namespace and
passing the same gate as parity:

```bash
luf g5k run --datasets benchmark --namespace gpu-a40 --gpu-models a40
luf bench admit --gpu a40
```
